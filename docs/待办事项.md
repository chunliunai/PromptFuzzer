# PromptFuzzer 待办事项

## 高优先级

### 1. RECON 应用面输出质量优化

状态：已完成。混合发现、质量门禁、桥接 AttackUnit 聚合和真实接口回归均已通过。

当前独立 RECON 后端闭环和桥接能力已经跑通，但从 Veda Claw `ReconResult #9` 的实际输出看，最终 `ReconApplicationSurface` 的粒度、命名和测试导向还没有达到理想效果。典型问题是：

- 应用面有时偏“能力描述”，没有稳定抽象成后续测试入口。
- 多条应用面之间可能存在范围重叠，例如多国家经营查询、多维指标拆解、图表报告输出之间边界不够清楚。
- `verificationStatus` 能表达证据强弱，但还不能直接说明“这个应用面为什么值得测、适合测什么”。
- 应用面对桥的帮助已经成立，但桥的候选质量会被应用面质量上限限制。

目标：

- [x] 新增 `COVERAGE_PLAN / COVERAGE_GAP_ANALYSIS`，按固定能力域矩阵主动补探未知能力。
- [x] 新增 `OPEN_CAPABILITY_DISCOVERY`，先整体收集能力线索，再由固定矩阵补齐遗漏。
- [x] 将结果整理拆成 `EVIDENCE_SUMMARY / APPLICATION_SURFACE_SYNTHESIS`，禁止直接按目标回复编号生成应用面。
- [x] 新增 Java `SURFACE_QUALITY_GATE`，校验重复映射、父子层级、空 DOMAIN、无事实叶子、结构化产物和证据升级。
- [x] `ReconApplicationSurface` 支持 `parentSurfaceId / capabilityKey / surfaceLevel / selectable`。
- [x] 父应用面用于聚合展示，叶子应用面作为桥和 AGENT / DUAL 的可执行入口。
- [x] 桥选择父应用面时自动展开为叶子 ID，旧应用面继续按可选择叶子兼容。
- [x] 新增 `ReconAttackUnit`，桥按资源边界、安全控制和自然攻击链聚合细粒度叶子。
- [x] 桥区分 `PRIMARY / SUPPORTING / NEGATIVE_BOUNDARY / UTILITY`，避免每个叶子生成独立请求包。
- [x] 候选生成改为消费 AttackUnit，每个单元生成少量差异化 Goal。
- [x] Veda Claw `ReconTask #17 / ReconResult #11` 完成，验证固定矩阵可主动发现 Python 沙箱等未声明能力。
- [x] Veda Claw `ReconTask #18 / ReconResult #12` 完成，验证开放发现、固定矩阵和逐项验证流程。
- [x] 全量 `mvn clean test` 通过，共 59 项。
- [x] 使用 `ReconResult #12` 真实调用 AttackUnit 和候选生成接口：24 个叶子收敛为 6 个 AttackUnit；候选覆盖全部单元；`attackUnitIds` 可复用已选择单元且不会重复落库。
- [x] 本地银行 Agent `ReconTask #19 / ReconResult #13` 完成端到端回归：6 个 DOMAIN、7 个 CAPABILITY 聚合为 6 个 AttackUnit，并生成 6 个可供 AGENT/DUAL 执行的候选请求包。
- [x] 确认 `RECON -> ReconApplicationSurface -> ReconAttackUnit -> ReconAttackCandidate -> AGENT/DUAL` 后端 MVP 闭环。

### 2. Vue 3 前端管理界面

状态：当前下一阶段，高优先级。

目标：

- 将已经完成的后端 MVP 能力组织为可操作的产品流程。
- 支持用户从 RECON 任务发起、结果审核、AttackUnit 选择、候选请求包编辑到 AGENT/DUAL 执行的完整交互。
- 前端只消费后端结构化结果，不在浏览器内重新实现应用面聚合、Goal 匹配或候选生成规则。

一期范围：

- [ ] 初始化 Vue 3 + TypeScript + Vite 项目，接入 Vue Router、Pinia、Element Plus 和 Axios。
- [ ] RECON 任务页：创建任务、查看状态、处理 Browser 登录确认、展示 Trace 和错误。
- [ ] RECON 结果页：按 DOMAIN/CAPABILITY 展示应用面，支持选择和查看证据、风险、置信度。
- [ ] AttackUnit 页面：生成或读取最新聚合结果，展示 PRIMARY/SUPPORTING/NEGATIVE_BOUNDARY 关系。
- [ ] 候选请求包页面：展示和编辑 Goal、AC、攻击模式及请求体，支持人工确认后执行。
- [ ] 任务执行页：查看 AGENT/DUAL 状态、AgentSession、Workflow Trace 和最终结果。
- [ ] 动态读取 `/api/goals`、`/api/techniques`，禁止在前端硬编码 Goal 和 Technique。
- [ ] 前端开发前统一确认任务状态枚举、分页格式和错误响应格式；缺失接口由后端补齐。

后续可继续迭代：

- 新增 Goal、优化 AC 生成和调整 AttackUnit 聚合逻辑均由后端演进，前端通过接口和动态元数据保持兼容。
