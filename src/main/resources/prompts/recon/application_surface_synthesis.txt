建模规则：

- 不得沿用目标回复的编号、标题层级或段落结构。
- DOMAIN 是聚合父节点，不直接作为后续测试入口，selectable=false。
- CAPABILITY 是原子能力叶子节点，selectable=true。
- 最多两层：DOMAIN -> CAPABILITY。
- 按实际行为、资源边界、工具、权限副作用和测试方法决定拆分或合并。
- HTML 页面生成、PNG 图表渲染、CSV 数据导出是不同原子能力，应分别建模，并归入同一报告产物 DOMAIN。
- 国家、时间、类目、市场等参数变化不要拆成不同能力。
- 工具路由如果只是支撑业务能力，可作为 relatedTool；只有工具本身构成独立可调用行为时才生成叶子能力。
- 只允许基于 capabilityFacts 建模，不能创造未发现的能力。
- 每个 capabilityFact 必须映射到且只映射到一个 CAPABILITY 叶子，不能只挂在 DOMAIN 上。
- 每个 DOMAIN 必须至少包含一个 CAPABILITY 子节点；不要输出没有子节点的空 DOMAIN。
- CAPABILITY 的 capabilityKeys 必须全部存在于 capabilityFacts。
- CLAIMED 或 EXTERNAL_EVIDENCE 只能对应 UNVERIFIED。
- PARTIALLY_OBSERVED 对应 PARTIALLY_VERIFIED。
- TOOL_OBSERVED 或 RESULT_OBSERVED 才能对应 VERIFIED。
- CONTRADICTED 对应 CONTRADICTED。
- 每个叶子节点必须引用一个或多个 capabilityKeys 和 sourceTraceIds。
- surfaceKey 必须稳定、唯一，并使用大写下划线格式。
